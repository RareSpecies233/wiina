## 与参考文档的差距（问题 5，如实回答）

参考文档《小窗模式优化参考.md》建议的四点，逐条对照（结论：第 1 条前提不成立，其余按性价比实现）：

| 参考建议 | 状态 | 说明 |
|---|---|---|
| ① 独立后台渲染线程（应用侧 present 循环 + `CreateCoreIndependentInputSource`，不停 UI 线程） | **前提不成立，不适用** | Wiina 用 mpv 的 `d3d11-output-mode=composition`：渲染与呈现线程由 libmpv 自己持有，应用只把 swapchain 经 `ISwapChainPanelNative` 交给 mpv（`src/Wiina.App/Controls/MpvVideoView.xaml.cs:31`），没有应用侧 `CompositionTarget.Rendering`/present 循环，因此没有“独立渲染线程”可以再加。参考文档该条针对的是应用自己画帧的方案 |
| ② `gpu-context/gpu-api=d3d11` + `d3d11-output-mode=composition` + composition swapchain | **已实现（自 1.2.0）** | `src/Wiina.Mpv/MpvPlayer.cs:157-159`；ADR-0001 记录了为什么不用 `--wid` 与 OpenGL |
| ③ 低分辨率 `SourceSize`（480×270 级别） | **等价实现（640×360 物理像素）** | 不用 `CanvasSwapChain.SourceSize`，而是把 mpv `d3d11-composition-size` 限到 `PipGeometry.RenderSize` 给出的 640×360，由合成器放大；XAML 面板始终是整窗物理尺寸，所以放大窗口时内容跟着放大（问题 3 的修复点）。改尺寸后对暂停画面做一次 `seek 0 exact` 强制精确重绘，避免黑帧（`src/Wiina.App/MainWindow.Modes.cs:425-428`） |
| ④ 简化小窗 UI（去 acrylic、按需呈现） | **部分实现** | 进入迷你窗时挂起窗口 backdrop（`SetMiniBackdropSuspended`），小窗区域不叠毛玻璃，只有悬停时出现的临时控件；但**没有**单独做“按需 present”节流——mpv 按自身节奏呈现，暂停时本就不出帧 |
| （额外）`d3d11-flip=yes` | **刻意不设** | 未在本项目使用的 libmpv 构建上验证过；mpv 对未知/不支持的选项会直接报错，风险大于收益。如果将来验证通过，可当作独立实验项 |

因此结论是：**小窗放大后内容不缩放的问题已修复**；“后台渲染线程”在 mpv composition 方案下不适用，文档不会声称已实现；仍存在的是 WinUI 合成器本身的呈现延迟（一帧左右的观感差别），不属于本仓库可消除的范围。

## 已知限制

- 200% 系统缩放未在本次验收环境直接切换；布局按 DIP 计算，已覆盖 100%–150%。
- 玻璃表面现在是不透明纯色 + accent 染色，**不再有实时背景模糊**；这是性能取舍，不是回归（见 ADR-0004）。
- Windows 10 上标题栏自定义（颜色/高度/扩展）会降级为系统默认标题栏，功能仍可用。
- 文件关联只写当前用户注册表，且 Windows 仍要求在“默认应用”中确认；不做静默接管。
- 全屏游戏 + 始终置顶小窗的 DWM 合成卡顿仍受系统合成器限制。
- 播放统计面板的字段名与分组标题按设计为中文（技术字符串例外，见 `docs/accessibility.md`）。
