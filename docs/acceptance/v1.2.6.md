## 构建与测试

```powershell
# Core 测试
dotnet test tests/Wiina.Core.Tests/Wiina.Core.Tests.csproj -c Release

# 应用（Release / x64 / self-contained）
dotnet build src/Wiina.App/Wiina.App.csproj -c Release -p:Platform=x64

# 或使用固定的开发构建脚本
pwsh -File scripts/dev-build.ps1 -Agent docs

# 便携 zip（含便携卸载器，校验 Wiina.dll 版本 == 1.2.6）
pwsh -File scripts/package.ps1 -Version 1.2.6

# 安装包（在便携 zip 之后；需要 Inno Setup 6）
pwsh -File scripts/release.ps1 -Version 1.2.6
```

> 不要用 `dotnet build Wiina.slnx -p:Platform=x64`：当前 SDK 不识别该平台名，请按上面的项目构建。

## 验收清单（本轮 5 项用户问题 + 2 项文档交付）

| # | 用户问题 / 交付 | 结果 | 证据 |
|---|---|---|---|
| 1 | 打开快速设置侧栏时 OSC 不应无谓移动，除非确实被遮挡；同类浮层也应遵守 | ✅ 已验（人工） | `MainWindow.ApplyOscPosition`（`src/Wiina.App/MainWindow.xaml.cs:1055`）只在 `top + oscHeight > SidebarPanelTop() + SidebarOverlapTolerance` 时横向夹取到侧栏边缘（`OscSidebarGap = 8`）；`SidebarLeading/Trailing.SizeChanged` 触发重算（:220-221），拖动结束与位置恢复走同一规则（:1002-1008、:1528）。Docked 底栏仍按分栏让位（布局行为，不是无谓平移）。人工验证：同一次播放中打开侧栏前后，浮动 OSC 的屏幕坐标不变（侧栏在右侧、OSC 在画面中下部未相交） |
| 2 | OSC 自动隐藏“发疯”：抖动续命、全屏停在控制条上不消失、失焦/点击行为不一致 | ✅ 部分验证（自动隐藏主路径） | `OscVisibilityController`（`src/Wiina.Core/State/OscVisibilityController.cs`）：5 DIP 双轴阈值、`Stopwatch` 单调空闲时钟、`ShouldHideOnIdle`、`ShouldHideOnDeactivate(docked, sidebarVisible)`、`ShouldHideOnClick`；`MainWindow.OnAutoHideTick`（:590）以空闲时钟为准而非计时器 tick（修复全屏停在上方不消失），`OnRootPointerExited` 立即隐藏（flyout/左键/侧栏除外），左键点击画面按“按下到抬起无明显位移”隐藏；Docked 从不自动隐藏、PiP/迷你忽略播放器 chrome。人工验证：延时设为 1.2 s 后鼠标静止，OSC 按时淡出；移动鼠标立即恢复。**人工发现并修复**：`DispatcherQueueTimer` 可能提前约 1 ms 触发，旧代码在 `ShouldHideOnIdle == false` 时直接停止且不再续排，导致控制条永久停留；现在 `OnAutoHideTick` 会按剩余时间重新 `Start()`（`MainWindow.xaml.cs:603-620`）。点击/失焦/全屏静止仍建议人工复验 |
| 3 | 自动隐藏延时必须可配置 | ✅ 已验（人工） | 新行 `ui.osc-autohide-seconds`（设置 → 界面 → 窗口与 OSC → 自动隐藏延时，0.5–30 秒，默认 2.5）：`SettingsCatalog.cs:171-175`、`AppSettings.OscAutoHideSeconds = 2.5`、`OscVisibilityController` 双重 clamp；启动时把 `_autoHideTimer.Interval` 同步为该值（`MainWindow.xaml.cs:277-278`），改值后同样重排（:701-703）。人工验证：`settings.json` 设为 1.2 s 后，静止约 1.2 s 即隐藏 |
| 4 | 音频输出设备应为设备下拉，而不是文本 | 待验（UI 已见） | 新 `SettingsRowKind.AudioDevice` + `src/Wiina.App/Services/AudioDeviceService.cs`：首项“跟随系统默认”，按描述显示、重名用原始名消歧，tooltip 显示原始 mpv 名；已保存但 mpv 未报告的设备显示为“不可用（…）”，不静默改写；刷新按钮重读主窗口缓存的 `audio-device-list`（不做轮询），切换立即下发 `audio-device`；`SettingsWindow.xaml.cs:619` 起为 `ComboBox + 刷新按钮`。人工确认下拉与刷新按钮已渲染；实际切换/热插拔仍待人工 |
| 5 | 调研 IINA 时间轴缩略图逻辑 vs Wiina（只调研，不实现） | ✅ 文档 | [../reference/iina-thumbnails.md](../reference/iina-thumbnails.md)：IINA 在打开时用 FFmpegController 预生成约 100 张缩略图并落盘缓存、悬停最近邻查找、无加载态、跳过流；Wiina 为悬停时用无头 libmpv seek 到 5 秒桶 + `screenshot-raw`、无磁盘缓存、有加载态、`File.Exists` 跳过流。**对齐工作未实施**，仅在 known-issues/performance 记录 |

## 已知限制

- 自动隐藏延时只影响非 Docked 布局；Docked 的标题栏与底栏按设计常驻。
- 悬停预览仍是每次悬停实时抽帧（无磁盘缓存、无预生成）；IINA 式预生成+缓存是对齐计划，未实现。
- 音频设备列表来自 mpv；播放器尚未启动时只有“跟随系统默认”，刷新按钮只重读缓存列表。
- 自动隐藏、OSC 避让手感、设备切换均需人工拖动/播放确认（上表为待验）。
- 644/659/668 等测试数字分别属于历史版本与本轮；本文档只采用本轮 668。
