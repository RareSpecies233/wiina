```powershell
$dotnet = "$env:USERPROFILE\.dotnet\dotnet.exe"

& $dotnet build src/Wiina.App/Wiina.App.csproj -c Release -p:Platform=x64
& $dotnet build tests/Wiina.Core.Tests/Wiina.Core.Tests.csproj -c Release

# 本机 vstest testhost 无法打开父进程句柄（Win32Exception 5），使用 in-process
# xunit runner 跑同一份编译产物；runner 是本地 harness，不提交。
& $dotnet artifacts/testrunner/wiina-testrunner.dll artifacts/testrunner/Wiina.Core.Tests.dll
```

### 实现范围与诚实说明

- 本机**没有可用的音频输出设备**：纯音频文件（wav/mka）会报“打开失败”，因此“音频自动进入 mini”只完成了代码路径 + 工具栏入口验证，最终需在有声卡的机器上打开一个 mp3/flac 复核。自动进入已加“成功才置位 + ApplyLoadedMedia 重试”，避免加载期切换失败后永久锁死。
- 侧栏毛玻璃：本机窗口无法前台激活，`CopyFromScreen` 抓不到动画帧；修复逻辑已按“动画期间不重绘、结束只重放一次”落地，逐帧验收需人工。
- 吸附抖动：已加 `[snap]` trace 与纯逻辑测试；真实鼠标多显示器/任务栏/150% DPI 仍需人工按 `docs/reports/fix-plan-1.3.11.md` §7 复核。
- 右侧 caption 按钮仍为自绘，残余 ≥1 帧延迟；原生 `AppWindowTitleBar` 改造按确认留到后续 UI 修复。
- mini 仍是主窗内覆盖层（非独立 HWND），这是本轮确认的范围；spec §10.1 的“独立窗口”记为未来项。
